## 1. 产品概述

### 1.1 产品定位

育才 HR 是一个面向本地（成都）劳动力市场的招聘平台，运行于**微信小程序**，将来同步支持 H5。核心差异点是引入**职业信用评分体系**，帮助企业识别诚信求职者，同时保护求职者的合法权益。

### 1.2 目标用户

| 用户角色 | 说明 |
|---------|------|
| 求职者 (Seeker) | 通过小程序找工作、投递简历、与企业沟通 |
| 招聘官 (Recruiter/HR) | 发布职位、浏览简历、邀请面试 |

### 1.3 平台规划

- **现阶段**：微信小程序（`dev:mp-weixin`）
- **未来**：H5（`dev:h5`，脚本已配置），可扩展至其他小程序平台

## 2. 用户流程

### 2.1 整体导航结构

```
启动
└── 登录页（pages/login/index）
    ├── 求职者端
    │   ├── 首页（pages/seeker/index）        ← Tab 1: 首页
    │   ├── 消息中心（pages/message/index）    ← Tab 2: 消息
    │   ├── 简历中心（pages/seeker/resumeCenter/index）← Tab 3: 简历中心
    │   └── 个人中心（pages/mine/index）       ← Tab 4: 我的
    │
    └── 招聘官端
        ├── 首页（pages/recruiter/index）      ← Tab 1: 首页
        ├── 消息中心（pages/message/index）    ← Tab 2: 消息（复用）
        ├── （简历中心，Tab 3）                ← 复用或单独
        └── （个人中心，Tab 4）                ← 复用或单独
```

> **问题 #1**：当前 BottomNav 组件的导航路径固定指向求职者路由（`/pages/seeker/index`、`/pages/seeker/resumeCenter/index`）。招聘官端的 BottomNav 逻辑尚未区分，招聘官首页 Tab 1 导航会跳到求职者首页。需确认双端切换机制。

## 3. 功能模块详述

### 3.1 登录模块

**页面**：`pages/login/index`

**功能：**
- 手机号 + 密码登录
- 手机号格式验证（1开头11位数字）
- 登录成功后跳转首页

**路由守卫：**
- 所有标记 `needLogin: true` 的页面，未登录时自动重定向到登录页，并携带 `redirect` 参数
- 登录成功后返回原目标页

> **问题 #2（关键）**：当前登录逻辑完全是 Mock（`uni.setStorageSync('token', 'mock-token-'+Date.now())`），没有调用任何后端 API。后端开发完成后需前端对接真实登录接口。

### 3.9 简历中心（求职者）

**页面**：`pages/seeker/resumeCenter/index`

**展示内容：**
- 个人基础信息（姓名、职业定位、手机号、头像）
- 自我描述
- 教育经历（时间线）
- 工作经历（时间线，含公司/职位/城市/薪资/技能标签）
- 项目经历（时间线，含项目名/角色/技术标签）

**操作：**
- 编辑个人信息 → 跳转 `resumeCenter/Information`
- 编辑自我描述 → 跳转 `resumeCenter/selfDesc`
- 添加/编辑教育经历 → `resumeCenter/education`
- 添加/编辑工作经历 → `resumeCenter/job`（新增：删除工作经历、编辑工作经历、申请工作认证）
- 添加/编辑项目经历 → `resumeCenter/project`（新增：删除项目经历、编辑项目经历）
- 查看工作认证 → `resumeCenter/workCertification`

**前端修改记录（resumeCenter/index.vue）：**
- 每条工作经历新增**删除**按钮（二次确认弹窗，调 `DELETE /v1/resume/work-exp/:id`，成功后从列表移除）
- 每条工作经历新增**编辑**按钮（跳转至 `job.vue?id=xxx`，job.vue 识别 id 后进入编辑模式）
- 每条工作经历新增**申请认证**按钮；认证中/已认证显示对应状态徽章
- 每条项目经历新增**删除**按钮（调 `DELETE /v1/resume/project-exp/:id`）
- 每条项目经历新增**编辑**按钮（跳转至 `project.vue?id=xxx`）
- 认证状态单独加载（不与主数据共用 `Promise.all`，避免加载失败导致整页空白）

**前端修改记录（resumeCenter/job.vue）：**
- 支持编辑模式：URL 带 `?id=xxx` 时，`onMounted` 加载已有数据回填表单，保存时调 `PUT /v1/resume/work-exp/:id`
- 页面标题根据模式动态显示"添加工作经历" / "编辑工作经历"

**前端修改记录（resumeCenter/project.vue）：**
- 支持编辑模式：URL 带 `?id=xxx` 时，`onMounted` 加载已有数据回填表单，保存时调 `PUT /v1/resume/project-exp/:id`
- 页面标题根据模式动态显示"添加项目经历" / "编辑项目经历"

**前端修改记录（resumeCenter/workCertification.vue）：**
- 替换 mock 数据为真实 `GET /v1/resume/certifications`，展示认证公司名和状态（认证中/已认证）
- 支持**确认模式**：URL 带 `?shareToken=xxx` 时（同事收到分享链接后打开），显示确认按钮，调 `POST /v1/resume/certify/:shareToken` 完成认证

**后端接口（resume 模块新增）：**
- `POST /v1/resume/work-exp/:id/request-cert` — 申请认证，生成 7 天有效 shareToken；如已认证则直接返回 APPROVED
- `POST /v1/resume/certify/:shareToken` — 同事确认认证；校验认证方在同公司已有 APPROVED 记录
- `GET /v1/resume/certifications` — 当前用户所有工作认证记录（含公司名、状态、shareToken）

> **注意**：申请认证要求工作经历已关联注册公司（`companyId` 不为空）。当前 job.vue 表单无公司关联入口，需后续补充（问题 #25）。

## 7. 运营端（管理后台）

### 7.1 定位与入口

运营端是面向内部运营人员的 **独立 H5 管理后台**，不在微信小程序内运行。

| 项目 | 说明 |
|------|------|
| 访问方式 | 浏览器直接访问（PC 优先） |
| 技术方案 | 独立 Vue3 + Element Plus H5 应用 |
| 账号体系 | 管理员账号由超管在后台创建，不走用户端注册流程 |
| 角色 | `ADMIN`（运营管理员）/ `SUPER_ADMIN`（超级管理员） |

### 7.2 登录

**功能：**
- 账号（手机号或邮箱）+ 密码登录
- 登录后根据角色显示对应菜单权限

### 7.3 数据概览（Dashboard）

首页概览展示核心运营指标：

| 指标 | 说明 |
|------|------|
| 注册用户总数 | 求职者 + 招聘官分开统计 |
| 今日新增用户 | 当日注册量 |
| 待审核实名认证 | 需人工处理的队列数量 |
| 今日投递量 | 简历投递总次数 |
| 职位总数 | 在线/下架/待审核分类 |

### 7.4 用户管理

**功能：**

| 功能 | 说明 |
|------|------|
| 用户列表 | 分页展示，支持按手机号/姓名/角色/注册时间搜索筛选 |
| 用户详情 | 查看基础信息、实名认证状态、简历概要、投递记录 |
| 禁用 / 启用 | 封禁违规用户账号，封禁后该账号无法登录 |

**MVP 不包含：** 批量操作、用户导出

### 7.5 实名认证审核

求职者提交实名认证后，运营人员在此模块人工审核。

**流程：**

```
求职者提交（上传证件照 + 填写信息）
    ↓
运营端审核列表（状态：待审核）
    ↓
运营人员查看证件照片、核对姓名与证件号
    ↓
通过 → 更新用户认证状态（idVerifiedAt 打时间戳）
拒绝 → 填写拒绝原因，求职者端显示审核未通过
```

**列表字段：** 提交时间 / 姓名 / 手机号 / 证件照预览 / 状态（待审核/已通过/已拒绝）

**操作：** 查看大图 → 通过 / 拒绝（填原因）

> 证件照存储于私有 COS 桶，审核通过后可删除原始图片。

### 7.6 工作经历认证（超管）

用于解决冷启动问题：系统初期无已认证用户，由超管直接为工作经历打上认证标记。

**功能：**

| 功能 | 说明 |
|------|------|
| 搜索用户 | 按手机号或姓名搜索 |
| 查看工作经历列表 | 显示该用户所有工作经历（公司/职位/时间/认证状态） |
| 直接认证 | 超管点击"认证"，无需关联认证人的工作经历，直接标记为已认证 |

> 仅 `SUPER_ADMIN` 有权操作；`ADMIN` 只可查看，不可认证。  
> 认证后该用户可作为"认证链"的起点，为同公司其他用户的工作经历进行认证。

### 7.7 职位管理

**功能：**

| 功能 | 说明 |
|------|------|
| 职位列表 | 分页，支持按公司/职位名/状态筛选 |
| 查看详情 | 查看职位完整信息 |
| 下架职位 | 强制下架违规职位（优先级高于招聘官的上架操作） |

> MVP 阶段不启用"职位发布需审核"流程，招聘官直接发布即上线；运营端保留强制下架能力。

### 7.8 企业管理

招聘官认证所属企业依赖企业库，运营端负责维护。

**功能：**

| 功能 | 说明 |
|------|------|
| 企业列表 | 分页展示全量企业，含认证状态 |
| 新增企业 | 填写企业全称、统一社会信用代码、所在城市、行业 |
| 编辑企业 | 修改企业信息、上传营业执照图片 |
| 认证企业 | 标记企业为"平台认证"，在用户端显示认证标志 |

**MVP 不包含：** 企业信用评分计算、企业信用异议流程

### 7.9 内容管理（轻量）

运营端可配置用户端首页展示的内容：

| 内容 | 说明 |
|------|------|
| Banner 轮播 | 上传图片、填写跳转链接、排序、启用/停用 |
| 最新动态 | 新增/编辑文章（标题/封面/正文/发布时间），供招聘官首页展示 |

> MVP 阶段以简单的图文录入为主，不需要富文本编辑器，纯文本即可。

### 7.10 运营端菜单结构（MVP）

```
运营端
├── 首页（Dashboard 数据概览）
├── 用户管理
│   ├── 用户列表
│   └── 实名认证审核
├── 认证管理
│   └── 工作经历认证（超管专属）
├── 招聘管理
│   ├── 职位列表
│   └── 企业管理
└── 内容管理
    ├── Banner 管理
    └── 动态管理
```
